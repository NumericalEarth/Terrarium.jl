Time stepping

Overview

Terrarium explicitly separates process computations in compute_auxiliary! and compute_tendencies! from the choice of time stepping scheme. As a general rule, only models can be configured for timestepping. A model can be initialized for timestepping via

source

A single iteration of the ModelIntegrator roughly involves four steps:

  1. Invoke update_inputs! to populate all input Fields from their respective InputSources based on the current clock time,
  2. Invoke compute_auxiliary! on all model components to derive auxiliary state variables from the current prognostic state,
  3. Invoke compute_tendencies! on all model components to calculate tendencies for all prognostic variables,
  4. Apply the tendencies computed in step (3) to update the prognostic state based on the selected timestepping scheme. Higher order explicit or implicit timesteppers may repeat steps 1-3 multiple times within a single time step.

Time stepping schemes

Each model carries a single timestepper (set via the timestepper keyword on the model constructor). LandModel, and SoilModel with Richards-equation water flow, default to the implicit-explicit IMEX(ForwardEuler(NF; Δt), BackwardEuler(NF)), with a time step of 15 minutes for LandModel and 1 hour for SoilModel (see Implicit-explicit time stepping); all other models, including SoilModel without water flow, default to ForwardEuler(NF), whose default time step is 300 s. Terrarium currently provides two explicit time steppers, ForwardEuler and Heun:

Implicit-explicit time stepping

Explicit schemes are cheap and simple, but for diffusive processes the stable time step shrinks quadratically with the grid spacing (see Adaptive time stepping). A thin surface layer or a fine vertical resolution can therefore force steps of seconds to minutes, even when the quantity of interest evolves over hours. Terrarium addresses this with an implicit-explicit (IMEX) time stepper, IMEX, which integrates selected prognostic variables with an implicit scheme and all remaining variables with an explicit one. Two variables can currently be integrated implicitly: the soil internal energy, via its vertical heat conduction operator, and the soil saturation, via the Darcy flux of the Richardson–Richards equation.

Terrarium.IMEX — Type

Structure of an IMEX step

A single IMEX step of size $\Delta t$ consists of the following stages:

  1. A single update_state! evaluates all inputs, auxiliary variables, and tendencies at $t^n$. For implicitly routed variables, the tendency holds only the explicitly treated terms $G_\text{exp}$; the implicit operator is omitted (see Routing variables below).
  2. update_cache! on the implicit sub-stepper's cache stores what it needs from $u^n$ (for BackwardEuler, a copy of $u^n$ of each implicitly routed variable) before the explicit stage overwrites it.
  3. The explicit sub-stepper's stage (explicit_stage!) is applied to all prognostic variables, giving $u^+ = u^n + \Delta t\, G_\text{exp}(u^n)$. For explicitly routed variables, this is the final result. For implicitly routed variables, it is the right-hand side of the implicit system.
  4. For the implicitly routed variables, implicit_step! of the implicit sub-stepper solves

    \[u^{n+1} = u^+ + \Delta t\, G_\text{imp}(u^{n+1})\]

    in place.
  5. The model hook timestep!(state, model, timestepper, Δt) and closure! are applied once, and the clock ticks once.

IMEX(ForwardEuler(NF; Δt), BackwardEuler(NF)) is the default timestepper of LandModel (Δt = 900) and of SoilModel with Richards-equation water flow (Δt = 3600). Under it, the snow meltwater drainage of a LandModel is implicit as well (see Implicit meltwater drainage), while the snow heat conduction, vegetation, surface hydrology, and surface energy balance remain explicit and are integrated with forward Euler at the same step; the shorter step of LandModel is set by the stability of the explicit snow heat conduction. Value boundary conditions on temperature or pressure_head (e.g. PrescribedSurfaceTemperature) require an explicit timestepper instead (see Limitations).

Because there is only one update_state! per step, an IMEX step costs one evaluation of the explicit right-hand side plus the implicit solve. The sub-steppers are given in the order IMEX(explicit, implicit), which is checked when the integrator is initialized. The explicit sub-stepper must be a single-stage scheme; currently this means ForwardEuler, whose Δt is also the default time step of the IMEX. The implicit sub-stepper is an AbstractTimeStepper whose behavior is further specialized by an AbstractImplicitSolver:

Routing variables

Which variables are integrated implicitly is determined by the timestepping trait, evaluated once when the integrator is initialized as timestepping(var, model, imex). The default for every variable is Explicit. SoilModel and LandModel both specialize it so that internal_energy is Implicit under any AbstractIMEX timestepper, via timestepping(::AbstractVariable{:internal_energy}, ::SoilModel, ::AbstractIMEX) = Implicit(). The soil saturation saturation_water_ice is Implicit as well whenever the soil hydrology follows the Richards equation (SoilHydrology with RichardsEq), and Explicit otherwise, as given by default_timestepping(hydrology). LandModel and SnowModel also route snow_water_equivalent implicitly, for the meltwater drainage (see Implicit meltwater drainage); the snow energy, vegetation, and surface hydrology variables always remain explicit.

To change the routing, define a more specific method for your own model type or timestepper type. For example, to keep soil energy explicit under a custom IMEX subtype MyIMEX, define timestepping(::AbstractVariable{:internal_energy}, ::SoilModel, ::MyIMEX) = Explicit(). The resolved class of each prognostic variable is stored in the type of the timestepper cache, so that routing is resolved at compile time and kernels remain type stable.

Implicit Euler with a Picard solver

The only implicit scheme currently provided is first-order backward Euler, BackwardEuler, with the Picard solver. When the integrator is initialized, BackwardEuler queries the model for the linearized operator of all variables routed to it with implicit_operator(model, state, names) and stores this single operator in its cache. For SoilModel and LandModel, it is a SplitOperator that holds a batched vertical TridiagonalOperator for each routed soil variable and solves saturation_water_ice before internal_energy (operator splitting; see Implicit solvers and Coupling of water and energy). BackwardEuler also resolves, for each variable, the field its linear system is solved for: the variable of its closure relation (as given by varname of the closure), i.e. the temperature for internal_energy and the pressure_head for saturation_water_ice, and for a variable without closure its implicit_variable, e.g. the snow_liquid_fraction for snow_water_equivalent. In each step, BackwardEuler stores the explicit increment $u^+ - u^n = \Delta t\, G_\text{exp}$ of every implicit variable in the ImplicitSolverWorkspace of the variable and resets all of their prognostic fields to $u^n$, and then calls the solver-level implicit_step!(solver, operator, workspaces, state, model, Δt) of its solver once; when a variable is solved, the solver forms its explicit stage from its current field and the increment. The solver iterates over linearizations of the operator, which it obtains from the process that owns each variable (see Enabling implicit timestepping):

Terrarium.Picard — Type
struct Picard <: Terrarium.AbstractImplicitSolver

Picard (lagged-coefficient) solver for the implicit system of a timestepper such as BackwardEuler. Each iteration linearizes the implicit operator of a prognostic variable at the latest iterate (linearize!), solves the linear system for the closure variable (e.g. temperature) with solve!, which dispatches on the AbstractLinearOperator (e.g. a batched tridiagonal solve for a TridiagonalOperator), updates the conserved variable conservatively (implicit_update!), and re-evaluates the closure (implicit_closure!). The solver is generic over the operator; the process-specific parts are the hooks, which the model forwards to the process that owns the variable.

A single iteration (iterations = 1) is the linearly implicit scheme used by most land surface models. The default of two iterations substantially reduces the lagged-coefficient error near freezing fronts and is the minimum recommended for the modified Picard iteration of the Richards equation [2].

Properties:

  • iterations::Int64: Number of Picard iterations (linearizations and linear solves) per implicit step

References

  • [2] Celia et al., Water Resources Research 26, 1483–1496 (1990)
source

For the soil energy equation (see Soil energy balance),

\[\frac{\partial U}{\partial t} = \frac{\partial}{\partial z}\left[\kappa \frac{\partial T}{\partial z}\right] - \frac{\partial}{\partial z}\left(C_\text{w}\, q\, T_\text{up}\right) + G_\text{exp}\,,\]

where the second term is the first-order upwind advection of sensible heat by the soil water flux $q$ (zero without water flow), and $G_\text{exp}$ contains the flux boundary conditions, the heat fluxes through the boundary faces, and any other explicit sources, the implicit step is a backward Euler step in temperature. Writing $C_\text{app} = \partial U / \partial T$ for the apparent heat capacity, the energy increment is linearized as $U^{n+1} - U^n \approx C_\text{app}\,(T^{n+1} - T^n)$, giving

\[C_\text{app}\, T^{n+1} - \Delta t\, \frac{\partial}{\partial z}\left[\kappa \frac{\partial T^{n+1}}{\partial z}\right] + \Delta t\, \frac{\partial}{\partial z}\left(C_\text{w}\, q\, T^{n+1}_\text{up}\right) = C_\text{app}\, T^n - U^n + U^+\,, \qquad U^+ = U^n + \Delta t\, G_\text{exp}\,.\]

This system is tridiagonal in each column and is solved with a batched tridiagonal solver. The coefficients $\kappa$ (at cell faces) and $C_\text{app}$ (at cell centers) are lagged, i.e. evaluated at the latest iterate rather than at $T^{n+1}$. The water flux $q$ is the flux with which the water was moved in the same step (see Coupling of water and energy); for a fixed $q$, the upwind terms keep the system an M-matrix, so the advection needs no CFL limit. The first iterate is the internal energy at the beginning of the step, $U^n$, stored by update_cache!, with the temperature re-diagnosed from it at the current saturation.

The FreeWater freeze curve has an apparent heat capacity that is a Dirac delta at the melting point, which cannot be used directly in a linear system. Terrarium therefore regularizes it: for cells undergoing phase change (liquid water fraction strictly between zero and one), the latent heat term is replaced by a large constant capacity,

\[C_\text{app} = C + C_\text{pc}\,, \qquad C_\text{pc} = 1.5 \times 10^8~\text{J/m}^3\text{/K}\,,\]

with bulk heat capacity $C$. Outside of phase change, $C_\text{app} = C$. For typical water contents, $C_\text{pc}$ corresponds to spreading the latent heat over an interval of roughly 1 K. Since the energy is updated conservatively (see below), $C_\text{pc}$ only affects how quickly the temperature of a freezing or thawing cell may change between iterates, not the energy balance.

Once the temperature has been solved for, the internal energy is updated conservatively from the implicit diffusive and advective fluxes through the interior faces,

\[U^{n+1} = U^+ + \Delta t\, \frac{\partial}{\partial z}\left[\kappa \frac{\partial T^{n+1}}{\partial z}\right] - \Delta t\, \frac{\partial}{\partial z}\left(C_\text{w}\, q\, T^{n+1}_\text{up}\right)\,,\]

rather than from the linearization. The temperature and liquid water fraction are then diagnosed from the closure, after every iteration including the last, so that they are consistent with $U^{n+1}$ when the implicit step returns. Since the interior fluxes cancel pairwise between adjacent cells, the change in the column-integrated energy over a step equals $\Delta t$ times the net boundary flux contained in $G_\text{exp}$, independent of the number of iterations and the regularization.

With iterations = 1, this is the linearly implicit scheme used by many land surface models. The default is iterations = 2. With iterations = M > 1, the lagged coefficients are re-evaluated at the new iterate (after re-applying the closure) and the solve is repeated, which is a Picard iteration on the nonlinear system [2]. A single step is still only first order accurate in $\Delta t$, but additional iterations reduce the error from the lagged capacity near freezing fronts.

Implicit Richards equation

For a Richards-equation hydrology, the implicit step solves the mixed form of the Richards equation (see Soil hydrology) with the mass-conservative modified Picard iteration of [2]. With porosity $\phi$, saturation $s$ (so that the volumetric water content is $\theta = \phi s$), and total hydraulic head $\Psi = \psi_m(\theta) + \psi_z + \psi_h$ (matric, elevation, and hydrostatic head), the backward Euler step reads

\[\phi\, \frac{s^{n+1} - s^n}{\Delta t} = \frac{\partial}{\partial z}\left[K \frac{\partial \Psi^{n+1}}{\partial z}\right] + \phi\, G_\text{exp}\,,\]

where $G_\text{exp}$ contains the flux boundary conditions on the saturation (e.g. InfiltrationFlux), the Darcy fluxes through boundary faces implied by gradient conditions on the pressure head, evapotranspiration, and the user-defined forcing. The elevation head and the hydrostatic head below the water table are held fixed within the step, so that $\partial\theta/\partial\Psi = C$, the specific moisture capacity. Linearizing the water content about the latest iterate $m$, $\phi s^{m+1} \approx \phi s^m + C^m (\Psi^{m+1} - \Psi^m)$, with the hydraulic conductivity $K^m$ of the Darcy flux lagged at the same iterate, gives the tridiagonal system

\[C^m\, \Psi^{m+1} - \Delta t\, \frac{\partial}{\partial z}\left[K^m \frac{\partial \Psi^{m+1}}{\partial z}\right] = C^m\, \Psi^m - \phi\,(s^m - s^+)\,, \qquad s^+ = s^n + \Delta t\, G_\text{exp}\,,\]

for the total head, starting from $s^0 = s^n$. As for heat conduction, the saturation is then updated conservatively from the implicit fluxes through the interior faces,

\[s^{m+1} = s^+ + \frac{\Delta t}{\phi}\, \frac{\partial}{\partial z}\left[K^m \frac{\partial \Psi^{m+1}}{\partial z}\right],\]

and the hydrology closure is applied after every iteration: it redistributes over- and undersaturation (see adjust_saturation_profile!), updates the water table, and recomputes $\Psi^{m+1}$ from $s^{m+1}$. Excess water that reaches a saturated surface is routed into the surface_excess_water pool of a LandModel's surface runoff only by the closure of the last iteration (and is discarded by a standalone SoilModel), since every iteration restarts from $s^+$. For the same reason, only the closure of the last iteration moves the heat of the redistributed water (see Coupling of water and energy), so the internal energy is adjusted exactly once per step. The column water content therefore changes by exactly $\Delta t$ times the boundary fluxes and sources in $G_\text{exp}$, minus the excess routed to the surface pool, for any number of iterations. The Darcy fluxes $-K^m \partial_z \Psi^{m+1}$ of the conservative update are stored in the water_flux auxiliary variable of the hydrology; after the last iteration, it holds the flux that moved the water in the step.

In saturated cells $C = 0$, and the diagonal of the system is carried by the conductivity terms $\Delta t K / \Delta z^2$. Where the conductivity vanishes as well (frozen saturated cells), the system would be singular, so $C$ is bounded from below by the small minimum_moisture_capacity (1/m, default $10^{-5}$) of the hydraulic properties (see ConstantSoilHydraulics), which acts like a small specific storage within the iteration but does not affect mass conservation. [2] recommend at least two iterations, which is the default of Picard.

Coupling of water and energy

With a Richards-equation hydrology, the water flux advects sensible heat: the soil energy equation carries the first-order upwind term $-\partial_z (C_\text{w} T_\text{up}\, q)$ (see Soil energy balance). For the scheme to keep a uniform temperature uniform, heat must move with exactly the water that moves. Terrarium ensures this as follows.

  • Water before energy. The SplitOperator of SoilModel and LandModel solves saturation_water_ice before internal_energy. The heat step therefore sees the saturation at the end of the step and the water flux of the step, while the Richards step sees the temperature and liquid water fraction at the beginning of the step: the effect of frozen ground on the hydraulic conductivity is lagged by one step, as in most sequentially split land models. The Stefan problem test (test/soil/soil_freeze_thaw_tests.jl) quantifies this against a fully explicit reference.
  • The water flux of the step. The water_flux auxiliary variable holds the Darcy flux through the cell faces that moved the water: the flux at $t^n$, computed with the tendencies, through the boundary faces and, under explicit time stepping of the saturation, through the interior faces; under implicit time stepping, the flux of the conservative update of the last Picard iteration through the interior faces. The advective heat fluxes use this flux, explicitly when internal_energy is explicit, and implicitly (upwind, in the heat operator) when it is implicit. In the implicit case, water that enters the column through a boundary face carries the temperature of the boundary cell at $t^n$ (explicitly), while water that leaves it, e.g. by gravity drainage, carries the temperature of the boundary cell at $t^{n+1}$ (implicitly), so that a large explicit drainage flux cannot remove more heat from the bottom cell than it holds. The heat carried by flux boundary conditions on the saturation (e.g. infiltration, see compute_boundary_advected_heat!) is explicit in both cases, since the water flux is.
  • Heat moved by the hydrology closure. adjust_saturation_profile! moves the sensible heat $C_\text{w} T$ of the water it shifts between cells, at the temperature of the cell that the water leaves, and removes the heat of the excess water that it discards or routes to the surface excess pool. The hydrology closure runs before the energy closure, so the temperature is recomputed from the adjusted energy. When both variables are implicit, the internal energy then holds $U^n$ plus this adjustment, and since the Picard solver forms the explicit stage of the heat step from the current internal energy and the explicit increment, the adjustment is kept, as in a sequential split.

The water heat capacity $C_\text{w}$ is the one with which water enters the bulk heat capacity. Since the bulk heat capacity also includes air, water that replaces air in the pores changes the temperature slightly (by a fraction of the order of $C_\text{air} / C_\text{w} \approx 3 \times 10^{-4}$ of the change of the water content), as the heat of the displaced air is not tracked.

Implicit water with explicit energy

Integrating saturation_water_ice implicitly while internal_energy is explicit (by specializing timestepping) is allowed, but not recommended with water flow: the explicit advection of heat is then computed at $t^n$, before the water is moved by the implicit flux of the step, so heat and water move with different fluxes. During wetting fronts, this can warm or cool the soil substantially and become unstable for large time steps. The default routing of SoilModel and LandModel integrates both implicitly.

Under explicit time stepping of internal_energy, the stability limit of the explicit advection is reported by cell_advection_timescale (see Adaptive time stepping); under implicit time stepping, it is Inf.

Example

We configure a SoilModel with an IMEX(ForwardEuler(Float32), BackwardEuler(Float32)) timestepper, a thawed initial column, and a constant cooling flux at the surface via SoilHeatFlux (positive upward, i.e. out of the soil). The default time step of the IMEX is that of its explicit partner. The time step of one hour is more than ten times the explicit stability limit of this column (roughly six minutes).:

    boundary_conditions = SoilHeatFlux(80.0f0),
    initializers = (temperature = 0.5f0, saturation_water_ice = 0.8f0),
)

end

Choosing Δt and iterations

The implicit step is unconditionally stable for the diffusion operator (the linear system is an M-matrix, so the temperature obeys a discrete maximum principle), but it is only first order accurate. The choice of Δt is therefore governed by accuracy and by the time scales of the explicitly treated terms (e.g. boundary forcing), not by the diffusive CFL. A useful reference is the explicit limit cell_diffusion_timescale; steps of tens to hundreds of times that limit are stable, and the error of the solution decreases linearly when Δt is halved.

Phase change is the main source of error. With iterations = 1, the lagged apparent heat capacity overestimates the cooling of cells that begin to freeze within a step. Using iterations = 2 reduces the maximum temperature error of a freezing front by roughly a factor of ten in the tests, at the cost of one additional coefficient evaluation, tridiagonal solve, and closure per step. More iterations are not guaranteed to reduce the error further, since the regularized capacity of a cell switches on and off as the iterates enter and leave the phase change. For thawed columns (no phase change), a single iteration is sufficient.

Limitations

  • Only the vertical heat conduction, the advection of heat by the soil water flux, and the Richards-equation Darcy flux in the soil can be integrated implicitly. The advection is first-order upwind and therefore numerically diffusive at large advective Courant numbers. Infiltrating water enters at the temperature of the top soil cell rather than at the skin or rain temperature, water removed by evapotranspiration carries no heat, and the surface excess pool stores no heat, i.e. the heat of the excess water leaves the system with it.
  • Value (Dirichlet) boundary conditions on temperature, such as PrescribedSurfaceTemperature, are rejected when internal_energy is implicit, with an informative error at initialization. Use flux boundary conditions on internal_energy, such as SoilHeatFlux and GeothermalHeatFlux, or an explicit timestepper. Gradient (Neumann) boundary conditions on temperature are supported; the flux $-\kappa\, \partial T / \partial z$ they prescribe is treated explicitly, at $t^n$, like a flux boundary condition.
  • Boundary fluxes are evaluated at $t^n$ and held fixed over the step; only the diffusive fluxes through interior faces are implicit.
  • With active soil hydrology (e.g. RichardsEq), the energy and water equations are coupled by operator splitting (see Coupling of water and energy): the Richards step evaluates the hydraulic conductivity at the liquid water fraction at $t^n$, so the effect of freezing and thawing on the water flow is lagged by one step. This affects only accuracy; energy and water conservation are unaffected.
  • The redistribution of water by adjust_saturation_profile! moves only the sensible heat of liquid water, also when the water it moves is frozen.
  • Boundary Darcy fluxes, e.g. gravity drainage, are evaluated at $t^n$ and are not limited by the water available in the boundary cell. At very large steps they can overdraw a column so strongly that it alternates between empty and saturated; the water solution is then inaccurate, and since the hydrology closure moves the excess water of a cell (and its heat) before the heat step advects the heat of the water that caused it, the temperature is then no longer guaranteed to stay within its initial range. A TimeStepWizard keeps the step below this bound through the explicit water outflow limit of cell_advection_timescale (see Adaptive time stepping with IMEX).
  • The meltwater drained by the implicit snow step reaches the soil in the following step (see Implicit meltwater drainage).
  • Value (Dirichlet) boundary conditions on pressure_head are rejected when saturation_water_ice is implicit; use flux conditions on saturation_water_ice (e.g. InfiltrationFlux) or gradient conditions on pressure_head (e.g. FreeDrainage).
  • Only the FreeWater freeze curve is supported, since the regularized apparent heat capacity is only implemented for it.
  • Heun is not yet supported as the explicit partner of an IMEX; use ForwardEuler.
  • The scheme is first order accurate in time.

Reactant and Enzyme

IMEX time stepping with the Picard solver and the TridiagonalOperator is tested both under Reactant (ReactantState grids, compiled with XLA) and for reverse-mode differentiation with Enzyme. The validity checks of the implicit operators run on the host when the integrator is initialized (in implicit_operator), so that the kernels contain no error paths. As with other timesteppers, adaptive stepping with a host-side TimeStepWizard does not apply to compiled Reactant runs.

Callbacks

Terrarium simulations inherit the full Oceananigans Callback machinery. A callback is a function that is called by Simulation at a given schedule during run!:

using Oceananigans: Callback, IterationInterval

function print_progress(sim)
    t = sim.model.clock.time
    iter = sim.model.clock.iteration
    @info "Iteration $iter, time $t s"
end

sim.callbacks[:progress] = Callback(print_progress, IterationInterval(100))
Callback of print_progress on IterationInterval(100)

The callback function receives the Simulation object, giving it access to the full integrator via sim.model, and to the current state via sim.model.state.

Adaptive time stepping

Some land components, such as the nonlinear advection-diffusion equations for soil energy, water, and carbon transport, are subject to stability constraints when using explicit time-stepping schemes like ForwardEuler or Heun. A suitable constraint is the diffusive Courant–Friedrichs–Lewy (CFL) condition. The standard formulation of the CFL for advective transport places a limit on the wave propagation speed based on the grid cell length $\Delta x$,

\[\frac{ \lvert v \rvert \Delta t}{\Delta x} \leq C\,.\]

While diffusive systems do not have an independent velocity $v$, they do have a characteristic length scale based on the diffusion coefficient $D$,

\[\ell \sim \sqrt{D \Delta t}\]

which we can understand as the distance over which information gets dispersed in a single time step $\Delta t$. Plugging that in as the numerator in CFL yields,

\[\frac{\sqrt{D \Delta t}}{\Delta x} \leq C\]

and solving for $\Delta t$ we get,

\[\Delta t \leq \frac{C^2 \Delta x^2}{D}\,.\]

Since $C$ is a constant, we can simply redefine $C_{\text{diff}} = C^2$. The choice of $C$ can be determined by von Neumann stability analysis for any given time stepping scheme; in the case of ForwardEuler, this leads to $C = \frac{1}{2}$.

Terrarium defines the diffusive CFL via the Oceananigans diagnostic cell_diffusion_timescale which is computed as the minimum over all grid cells of the diffusive timescale $\tau = \Delta z^2 / D$. For the soil model it is the minimum of the thermal timescale $\Delta z^2 C / \kappa$ (heat conduction, with thermal conductivity $\kappa$ and volumetric heat capacity $C$) and, for a Richards-equation hydrology, the hydraulic timescale $\Delta z^2 (\partial\theta/\partial\psi) / K$ (with hydraulic conductivity $K$ and specific moisture capacity $\partial\theta/\partial\psi$).

Because a ModelIntegrator implements the Oceananigans model interface, this diagnostic can be consumed directly by the Oceananigans TimeStepWizard callback, which rescales simulation.Δt each time it is invoked to target a chosen diffusive CFL number. The following examples use ForwardEuler explicitly, since an IMEX timestepper imposes no diffusive restriction from implicitly integrated terms (see Adaptive time stepping with IMEX). Attach it to a Simulation like any other callback,

integrator = initialize(SoilModel(grid; timestepper = ForwardEuler(Float32)))
sim = Simulation(integrator; stop_iteration = 50, Δt = 60.0)

wizard = TimeStepWizard(diffusive_cfl = 0.5, max_change = 1.1)
sim.callbacks[:wizard] = Callback(wizard, IterationInterval(5))

run!(sim)
sim.Δt   # adapted time step (s)
171.187f0

or more succinctly via conjure_time_step_wizard!:

integrator = initialize(SoilModel(grid; timestepper = ForwardEuler(Float32)))
sim = Simulation(integrator; stop_iteration = 50, Δt = 60.0)
conjure_time_step_wizard!(sim, show_progress = false)
run!(sim)
sim.Δt   # adapted time step (s)
572.59076f0

Oceananigans also defines a companion advective diagnostic cell_advection_timescale, which the wizard multiplies by its cfl (0.2 by default). For a soil with Richards-equation hydrology, it is the minimum of two time scales of explicit transport terms:

  • the stability limit $C \Delta z / (C_\text{w} |q|)$ of the explicit upwind advection of heat by the Darcy flux $q$ (with bulk and water volumetric heat capacities $C$ and $C_\text{w}$), Inf without water flow;
  • the explicit water outflow limit water_outflow_timescale, $\phi (s - s_\text{res}) \Delta z / q_\text{out}$, the time in which the explicit terms of the saturation tendency would drain a cell of porosity $\phi$ and saturation $s$ to its residual saturation $s_\text{res}$. The outflow $q_\text{out}$ (m/s) is the net loss of water of the cell per unit area through these terms: the Darcy fluxes that are integrated explicitly, the flux boundary conditions on the saturation (e.g. InfiltrationFlux), evapotranspiration, and the user-defined forcing. Cells without net explicit outflow impose no limit.

The wizard calls these diagnostics after each step, when the auxiliary variables have been updated but the tendencies are those of the beginning of the step. The outflow limit is therefore evaluated directly from the current state by kernel functions (compute_water_outflow_timescale) rather than read from the stored tendency, so that it measures the explicit outflow of the next step.

Adaptive time stepping with IMEX

Implicitly integrated operators impose no stability restriction, so the wizard is not throttled by them: under an IMEX timestepper, cell_diffusion_timescale is Inf for implicit heat conduction and implicit Richards flow, and the advective limit of the heat advection is Inf when internal_energy is implicit. The step is then bounded by the terms that remain explicit and by max_Δt. Without water flow, only max_Δt remains:

wizard_integrator = initialize(SoilModel(imex_grid; timestepper = IMEX(ForwardEuler(Float32), BackwardEuler(Float32))))
sim = Simulation(wizard_integrator; stop_iteration = 50, Δt = 60.0)
wizard = TimeStepWizard(diffusive_cfl = 0.5, max_change = 1.5, max_Δt = 6 * 3600.0)
sim.callbacks[:wizard] = Callback(wizard, IterationInterval(1))
run!(sim)
sim.Δt   # reaches `max_Δt`, far beyond the explicit diffusive limit of a few minutes
21600.0f0

With a Richards-equation hydrology, the Darcy fluxes through the boundary faces of the column (e.g. gravity drainage through a FreeDrainage or unit-gradient condition on pressure_head), the flux boundary conditions, and the sinks stay explicit at $t^n$ (see Implicit Richards equation). A step longer than the outflow limit would remove more water from a cell than it holds, and the hydrology closure would then move water from other cells to fill the deficit, so the column alternates between drained and saturated cells. The outflow limit keeps the wizard below this bound. In a draining sandy column, it can be as restrictive as the explicit diffusive limit of the Richards equation, since the boundary drainage carries the full flux through the column; the cfl of the wizard sets the fraction of the available water that a step may remove. Under explicit time stepping of the saturation, the outflow limit includes the interior Darcy fluxes, but the diffusive limit is then usually the more restrictive one.

If internal_energy is routed explicitly while saturation_water_ice is implicit (see the warning in Coupling of water and energy), the advective limit of the explicit heat advection and the diffusive limit of explicit heat conduction both apply.

Richards equation is stiff near saturation

As the soil saturates, $\partial\theta/\partial\psi \to 0$ and the hydraulic timescale tends to zero. Explicit integration of the Richardson–Richards equation is therefore extremely stiff in the saturated limit, which is the regime that motivates implicit time stepping. Implicit integration of the Richards equation removes this restriction (see Implicit Richards equation). The TimeStepWizard's min_change bound prevents Δt from collapsing to zero in a single adjustment, but a saturated explicit run may still require very small steps.

Reactant

Adaptive stepping applies to host-driven Simulations only. Under a ReactantState grid the time step is compiled into the traced run! loop, so a host-side wizard callback does not take effect there.

Output writers

We can make use of Oceananigans.OutputWriters to flexibly save output to disk in a variety of formats.

The simplest choice output writer is JLD2Writer which saves selected Fields to a .jld2 file at a specified schedule:

using Oceananigans: JLD2Writer, TimeInterval
using Oceananigans.Units: hours

output_file = "$(tempname()).jld2"
println("Writing output to $(output_file)")

sim = Simulation(integrator; stop_time = 24*3600.0, Δt = 300.0)
sim.output_writers[:soil] = JLD2Writer(
    integrator,
    (temperature = integrator.state.temperature,
     saturation  = integrator.state.saturation_water_ice);
    filename = output_file,
    overwrite_files = true,
    schedule = TimeInterval(2hours),
)

# Re-initialize integrator
Terrarium.initialize!(integrator)

# Run the simulation again
run!(sim)
